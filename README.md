# DaC+AI 产品管理工作流试验

## 试验简介
- **项目目标**：实践“文档即代码（Doc as Code）+AI”工作流，实现产品文档的结构化管理、AI 辅助生成与优化，构建随产品迭代持续更新的“活文档”体系。
- **核心思路**：
  - 以标准化模板为基础初始化文档，通过聊天型 AI（如 DeepSeek）生成初稿后
  - 经人工补充与 AI 优化完成内容迭代；
  - 按规范目录存储并纳入版本控制，同步建立与线框图、API 文档等资源的关联；
  - 利用 Replit AI 能力（Assistant/Agent）进行动态校验
  - 形成“模板初始化→内容迭代→结构化存储→关联建立→动态校验”的闭环，支持按需持续更新。
- **试验对象**：
   以本仓库的【LARMS_Project】作为模拟项目示例，进行DaC+AI 产品管理工作流的试验



## 文档结构
- **目录规范**

- **核心文档类型**
  - 实践中：重点产出页面功能说明文档，包含页面路径、功能模块、操作逻辑等基础内容（已完成部分页面的初稿）。
  - 计划尝试：补充用户画像、用户旅程等支撑性文档（待启动）；探索数据模型文档与页面功能说明的关联格式（设想中，未实践）。

- **模板说明**
  - 实践中：使用简易Markdown模板撰写页面功能说明，包含基本信息、功能模块、业务场景等核心模块（已小范围试用）。
  - 计划尝试：细化模板中的交互流程（如添加mermaid流程图标准格式）、异常处理等模块（正在调整模板结构）；制定术语表（`glossary.md`）并关联至模板，确保术语一致性（设想中，未落地）。

## AI 辅助工作流
- **文档生成与迭代**
  - 实践中：通过T3等聊天型AI交流，输入功能矩阵、模块要求等信息，由AI输出业务流程、功能模块思路等内容，再通过人工提出改进意见、AI二次迭代的方式完成初稿（已验证该模式可行性）。
  - 计划尝试：基于标准化模板，让AI批量生成文档框架，再由人工填充细节（此为设想，尚未大规模实践）；探索AI自动识别需求变更并提示文档更新的可能性（待实践）。

- **存储与版本管理**
  - 实践中：在Replit IDE中按规划的目录结构（如`02-UI-Wireframes/page-descriptions/`）存放Markdown文档，采用“页面名称+page.md”的命名格式（初步落地）。
  - 计划尝试：通过`changelog.md`记录文档更新历史，在文件元数据中添加版本号、更新时间等信息（正在搭建基础框架）；探索将文档纳入Git版本控制的具体操作流程（设想中，未完全落地）。

- **关联与校验机制**
  - 实践中：非正式的通过目录结构、文件内描述、文件命名规则，视图建立文件单元间关联
  - 计划尝试：利用Replit Assistant检查文档间关联的准确性（初步测试，尚未形成固定流程）；探索AI Agent自动识别文档依赖关系（如页面功能与API需求的匹配性）并生成校验报告的可行性（设想中）；定期让AI遍历文档目录，识别缺页、断链等问题（待实践）。

## 进度与计划

  1. 搭建目录 & 文档模板：
     - 确定项目仓库最小可用的目录模板

  2. 完善文档元数据：

     - 在文档模板中纳入元数据框架，人工遵守执行
     - 探索使用CI或AI工具，在创建文档时候，字段填充文档元数据
     -
  3. 制定AI交互规范
      - 创建专门的.rules类文件，定义AI如何阅读文档结构、处理文档模板等
      - 建立术语表（glossary.md），确保AI理解产品特定术语
  
  3. AI助手设定：
     - 编写辅助助手:在Replit配置prompt写入SYSTEM级assistant设定（待办）

  4. 定期维护：
     - 用 markdown-lint＋链接检查跑一次 Git 钩子，建立基础 CI。
     - AI巡检：两周发起一次 Assistant 质检对话：列缺页、断链并生成 TODO。（存疑，是不是可以用CI实现？）
  
### 后续计划

  1. 构建文档知识图谱
    - 页面→功能→API的关联关系

    - 实现增量更新和差异分析

    - 从需求分析到交付验收的全程文档管理
